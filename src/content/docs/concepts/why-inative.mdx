---
title: Why iNative?
description: Why a local IBM i development environment matters.
---

IBM i development normally requires access to a machine: compile there, run there,
debug there. iNative moves that loop to your machine:

```text
Source → Compile → Validate → Bind → Run → Debug
```

- **Learn RPGLE/ILE** without an IBM i partition.
- **Prototype** display files, programs, and service programs locally.
- **Report differences**: every behavior gap against IBM i becomes a tracked
  [compatibility case](/community/ibmi-cases/), which drives conformance work.

See [what works today](/compatibility/matrix/) before assuming coverage.
